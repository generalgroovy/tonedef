## Experience

Practice puts the goal, key and **New pattern** before optional generation details. Length, string pool, grouping, reach, rhythm, picking and their random flags remain in **Shape next pattern → More choices**. Random key/scale stay next to those choices. Existing saved music changes only through the normal explicit generation/edit transactions.

The simple-view header stays visible while scrolling, keeping the single Play/Stop control reachable beside the neck on a phone. Standard action buttons use `touch-action: manipulation` to avoid deferred double-tap click handling while preserving browser scrolling and pinch zoom. Fret and range gestures retain their own touch policy.

**Play along** uses the guitar guide. **Listen → play** performs the chosen passage once, then follows the same steps without guitar sound while a click marks the pulse. Repeat repeats that pair. **Count in one bar** defaults on in Practice and runs only once per start. The one header Play/Stop button describes its scope; Escape stops playback, including count-in and asynchronous audio unlock. Learn and Studio continue normal whole-pattern playback. Changing workspace stops playback. These controls are session choices, not musical settings subject to randomization.

**Whole pattern · choose passage** contains inclusive first/last step inputs, draggable endpoints and a whole-range grip, plus Just selected step and Whole pattern. Keyboard arrows, Shift+arrows, Home/End and Escape use the shared range controller. Touch, pointer cancellation, blur, lost capture and rerender cancel previews safely. Numeric entries reject invalid/crossed/out-of-pattern ranges. A single-step range has finite geometry. Passage changes stop playback and do not enter project history, truncate notes or affect export. Reordering or changing event music resets to the whole pattern; selection, locks, tempo, view changes and future generation rules retain the range. Reload starts a new session.

The timeline dims cards outside the passage and marks its endpoints. Playing cards follow the audio clock and scroll horizontally into view without moving the page. The count-in prepares the passage's first shape on the neck. During both turns, the current exact physical chord/note remains highlighted. The response turn still displays the visual guide; it is not a memory test. Use Challenge yourself → Hide hints for recall. The step guide stays hidden even when playback callbacks update it.

The **step guide** below the neck offers Previous / Hear / Next when stopped. It displays actual note names, physical string/fret or chord pitches, saved duration in quarter-note beats, and actual picking direction. Alternating strokes retain their original event index even when hearing a single step or starting a passage. A single-note move uses spelled `intervalBetween` and full interval words, preserving quality, direction and octaves. Chord transitions explicitly describe only lowest-to-lowest motion and point to Studio for other pitch ranks. Rests remain timed silence. Theory describes the previous chronological event, not an inferred voice or scale membership. All HTML descriptions escape source text.

**Check your progress** is the existing self-assessment, now scoped to the actual passage. Changing that range clears its streak and best. Tempo changes remain normal undoable project edits. Clean/Needs work never records microphone input or grades performance. No practice result persists after reload.

## Timing and implementation

- `src/audio.js`: `playbackPlan(project,{from,to,countIn,response})` accepts inclusive zero-based indices, validates bounds, constructs the complete source event strokes first, then rebases the selected events using integer tick sums at 96 PPQ. This preserves reentrant-string strum order and original alternate-picking parity. `passDuration = selectedTicks * 60 / tempo / 96`; a response cycle lasts twice that. Answer events retain IDs/durations and have empty sounding-note arrays. Source events stay immutable.
- The prelude is one meter bar; it is outside the repeating event cycle. The scheduler places clicks/notes using the Web Audio clock and the existing 120 ms lookahead. Third callback argument supplies phase, pulse number, pulses per bar and cycle number. Voice cancellation and revision checks cover Stop and pending AudioContext resume.
- Quarter-note BPM remains the tempo unit. In 6/8, 9/8 and 12/8 the click/count-in pulse is a dotted quarter (144 ticks): two, three and four pulses per bar. In the supported simple and asymmetric meters the denominator supplies the pulse; 7/8 is seven evenly counted eighths, not an inferred 2+2+3 grouping. Each passage turn restarts its pulse at its first step. If the chosen passage ends between pulses, the next turn begins immediately with its own pulse 1; it is a phrase loop, not a promise to preserve the original bar phase. Count-in clicks always sound at current volume; guide clicks obey Metronome, and answer clicks always sound at current volume.
- `src/focused-practice.js`: pure range/identity/step-insight functions plus the session controller. `installWindowTracks` accepts an ownership predicate so passage and saved practice-range controllers cannot process each other's events. The single-value window divides by at least one.
- `src/app.js`: scoped player options, selected-step audition, phase/neck/timeline updates, disclosure/focus preservation and passage-scoped coach. `src/practice-view.js` groups generation depth without duplicating controls. `workspace.css` makes stage status replace the stopped step-navigation row during playback, keeping the neck and explanation together. Stacked layouts include an explicit jump to the neck.
